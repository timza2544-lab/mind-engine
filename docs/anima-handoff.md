## 1. ตัวแอปคืออะไร และอยู่ที่ไหน

- **Anima Character Studio** คือแอปเว็บหน้าเดียว (HTML + JS ล้วน ไม่มีเซิร์ฟเวอร์) สร้างและแก้ตัวละคร สัมภาษณ์ตัวละคร และมีโหมดเกมหลายโหมด เนื้อหาเป็นภาษาไทย เป็นงานเขียนสำหรับผู้ใหญ่
- **ไม่ได้อยู่ในรีโปนี้** อยู่ใน Claude **Artifact** ชื่อ "Anima Character Studio" (ส่วนตัวของเจ้าของ) หา URL ด้วย Artifact `action: "list"`
- Artifact มี 29 ไฟล์ (หน้าหลัก `index.html` + ไฟล์ JS) อ่านรายชื่อด้วย `action: "list", scope: "files"` และอ่านไฟล์ด้วย `action: "read", paths: [...]` ไฟล์จะถูกบันทึกในโฟลเดอร์ scratchpad ของ session นั้น
- สถานะตอนเขียนเอกสารนี้: Artifact เวอร์ชัน **131**

## 2. วิธีทำงานกับไฟล์ขนาดใหญ่ (ประหยัดโทเคน)

อย่าอ่านทั้งไฟล์ ข้อความไทยจำนวนมากกินโทเคนหนัก (แอปทั้งหมดรวมหลายล้านโทเคน)

1. ดาวน์โหลดเฉพาะไฟล์ที่ต้องใช้จาก Artifact
2. ค้นด้วย `grep -n "<คำ>"` (ตัดบรรทัดด้วย `cut -c1-200`) แล้วอ่านเฉพาะช่วงรอบจุดที่เจอ
3. งานโหมดสามสิบนาทีส่วนใหญ่แตะแค่ `toxin.js` ไฟล์เดียว
4. สร้างการทดสอบด้วย Node (ดูหัวข้อ 8)

## 3. วิธีเสียบโหมดใหม่เข้าแอป (รูปแบบที่ใช้อยู่)

โหมดหนึ่งตัวประกอบด้วย 4 จุดต่อ:

1. **`index.html`**: เพิ่ม `<script src="<ชื่อ>.js"></script>` (ต่อท้าย `cards.js`)
2. **`views.js` ใน `renderGame`**: เพิ่มสาขา `if (G.mode === '<โหมด>' && A.<โหมด>) { el.innerHTML = ... A.<โหมด>.html() ... }`
3. **`views.js` ตัวส่งคำสั่ง**: เพิ่ม `if (/^<คำนำหน้า>/.test(act) && A.<โหมด>.onAct(act, t)) return;` (วงไพ่ใช้ `cd`, สามสิบนาทีใช้ `tx`)
4. **ปุ่มเข้าโหมด**: ต่อท้ายปุ่มวงไพ่ (`🃏 วงไพ่สองคู่`) ใน `views.js` ด้วยปุ่ม `data-act="<คำนำหน้า>open"`

โมดูลต้องมี `X.html()` กับ `X.onAct(act, el)` และเรียกบันทึกด้วย `ui.saveUI(); ui.renderMain()` หลังแก้สถานะ

## 5. สิ่งที่แก้ในไฟล์เดิม (นอกจาก `toxin.js`)

**`cards.js` (วงไพ่)**
- `gameOf(w)` ตัวช่วยกลางที่สร้าง `w.game.attempts` ให้เสมอ (แก้บั๊ก "Cannot read properties of undefined (reading 'attempts')" ที่เกิดเพราะ `ov()` ทำสำเนาตัวละคร)
- `C.start` ห่อด้วยตัวเก็บ snapshot: แจกล้มกลางทางคืนสถานะเดิม และย้อนหลังแจกได้ (`C.undo`, ปุ่ม `cdundo` / `cdredo` กดสองครั้ง) จุดย้อนอยู่ในหน่วยความจำ รีโหลดแล้วหาย
- สมุดความสัมพันธ์ข้ามคืน `w.game.ties[otherId]` (`C.recordTies`, `C.tiesTilt`, `C.tiesLine`), ฉากจบใหม่ `exposed`, `reunion`
- ขีดจำกัดโต๊ะ `C.LIMITS` (เก็บใน `S.cardsPick.limits`), seed (`id.roll`) คัดลอก/ใช้ซ้ำได้, แผง "ทำไมถึงออกฉากนี้" (`C.whyHTML`, `m.finaleWhy`)
- `C.notice` แถบข้อผิดพลาดแบบค้างพร้อมปุ่มคัดลอก, `C.selfTest` ปุ่ม "🧪 ทดสอบระบบ" (ตอนนี้เรียก `A.toxin.selfTest` ต่อท้ายด้วย)

**`logic.js`**: `A.gameChatNote` อ่าน `c.game.ties` ใส่ในบริบทสัมภาษณ์; `A.flowOf` (ใหม่) คำนวณน้ำไหลย้อนหลังแตกในจากปริมาณ ความข้นหนืด (`semen.visc`) กล้ามเนื้อเชิงกรานและความกว้างของเธอ และท่า ผลอยู่ที่ `release.semen.flow` / `.flowback` และแทรกเป็นบรรทัด "หลังเสร็จ น้ำไหลย้อนออกมา" ใน `A.releaseText` (ทุกโหมดที่เรียก `releaseText` ได้ผลอัตโนมัติ: เกมหลัก วงไพ่ ห้องกระจก รู สามสิบนาที) พร้อมต่อท้าย `A.RELEASE_RULE`

**`views.js`**: จุดต่อของโหมดใหม่ (หัวข้อ 3) และบรรทัดน้ำไหลย้อนในการ์ดผลเกมหลัก; **`trio.js`**: บรรทัดน้ำไหลย้อนของคนที่สอง; **`cards.js`** `outOf`/`resHTML`: แสดงน้ำไหลย้อนในผลวงไพ่

**ข้อจำกัดที่รู้อยู่:** ส่วนนำเข้าไฟล์ใน `views.js` (ราวบรรทัด 1669) ใช้ whitelist ของ `game` ที่ไม่เก็บ `game.mate` และ `game.ties` ถ้านำเข้าไฟล์สำรองข้อมูลทั้งสองอย่างจะหาย ยังไม่ได้แก้ (ไม่ได้รับคำสั่ง)

## 6. `toxin.js` (โหมดสามสิบนาที ปี 2069)

### แนวคิด
เขามีพิษในอัณฑะ ต้องปล่อยเข้าไปในผู้หญิงภายใน 30 นาที ไม่มีแฟนในโลกนี้ ญาติถูกเรียกก่อน ทำได้ทุกที่ ฉากเดียวจบ **ไม่เขียนอะไรลงตัวละคร แชท หรือสมุดความสัมพันธ์** (ยกเว้นปุ่มสุ่มคนใหม่ที่สร้างตัวละครเข้าคลังจริง)

### ลำดับใน `X.run(me, w, o)` (ทอยทั้งหมดมาจากเมล็ด `${o.id}:tx:${o.roll}`)
1. เลือกสถานที่, ชุด, ฝ่ายนำ, ตัดสินเซอร์ไพรส์ (`sids`)
2. `X.registry` จัดคิวผู้ช่วย (ญาติถึงตัวเร็ว ติดภารกิจน้อย) เรียกได้สูงสุด 3 คน ติดภารกิจ/ปฏิเสธ/ตอบรับ
3. `X.historyOf` ประสบการณ์ร่วม แล้วคำนวณลังเล
4. รีดพิษ 1–3 รอบ (4 รอบถ้ามีเซอร์ไพรส์ stamina): แต่ละรอบเรียก `A.gameRoll` พิษเริ่ม 100% ลดตามปริมาณ/ปริมาณปกติ × 72% × ความเข้ากันได้
5. `X.finishOf` สร้างรายละเอียดการแตกในต่อรอบ, `X.anatLine` สรีระต่อรอบ
6. ผลลัพธ์ (`cured/partial/collapse/death`), การตั้งครรภ์, เซอร์ไพรส์ที่ขึ้นกับผล
7. คืนออบเจ็กต์ผลลัพธ์ (`tl`, `rounds[]`, `fert`, `hist`, `anat`, `surprises[]`, `outfit`, `lead`, ...)

### ส่วนอื่น
- `X.kinProfile` สร้างญาติใหม่: คัดลอกลักษณะที่คล้ายตัวฉัน, นามสกุลตามสายเลือด, ความทรงจำ 3 เรื่องเขียนลง `sim.history`, คำเรียกกัน (`callHim/callHer`) และฟิลด์ของตัวเอง `sim.tx*` (`txLabel`, `txCat`, `txShared`, `txTemper`, `txQuirk`, `txWorld`, `txTwist` ฯลฯ)
- `X.prompt` ประกอบพรอมต์เต็มจากบล็อกของแอป (`<her>`, `<him>`, `<bond>`, `<anatomy>`, `<shared>`, `<surprise>`, `<finish>`, `<poison>`, `<release>`, `<after>`, `<style>`); ถ้าไม่พร้อมถอยไป `X.promptLite`
- `X.scene` เรียก Claude สตรีมเข้า `#txScene`
- `X.addrOf` สรรพนามและคำเรียกตามฐานะญาติและอายุ (พี่/น้อง/หนู/ผม/ป้า/น้า/อา/หลาน, คำลงท้าย) เก็บใน `sim.txAddr` ของญาติที่สร้างใหม่ และอนุมานจากป้ายบทบาทหรืออายุสำหรับตัวละครเก่า ส่งเข้าพรอมต์เป็นบล็อก `<address>` และแสดงในกล่องความสัมพันธ์; ญาติสายเลือด/ครอบครัวที่ใกล้เคียงกันใช้ภาษาเป็นกันเอง (เรา/ชื่อ) ส่วนคนไม่สนิทที่ไม่ใช่ญาติใช้ ฉัน/คุณ/ค่ะ-ครับ
- ตั้งค่าเก็บใน `S.toxinPick` (`pk()`): `death`, `ec`, `refuse`, `dispatch`, `crisis`, `surprise` (off/on/wild), `heat` (std/high/max), `format` (story/interview/log), `off` (รายการที่ปิดในแคตตาล็อก `{s,f,k}`) บันทึกใน localStorage คีย์ `anima.toxin.v1`
- แคตตาล็อกในหน้าตั้งค่า (`txoff`, กลุ่ม `s` เซอร์ไพรส์ / `z` สถานการณ์ / `f` รูปแบบการแตกใน / `k` บทบาทญาติ) ปิดทีละรายการ ใช้กับการสุ่มทั้งหมด

### เนื้อหา (นับตอนนี้)
- บทบาทญาติ/คนสนิท 30 แบบ (`NEW`), มีมาตรฐาน `KIN_KEYS`
- รูปแบบการแตกใน 58 แบบ (`FSTYLES` + `FSTYLES2..6`) พร้อมมิติเสริม: ช่วงเวลาระหว่างกัน, เสียง, สารในตัวเธอ, ข้างในเธอ, สีหน้า, คำเสียงประกอบ, ความคิดในหัว, คำพูด
- เซอร์ไพรส์ 47 แบบ (`SURP`, ชื่อใน `SURP_T`, กลุ่มหนักใน `SURP_WILD`)
- สถานการณ์พิเศษ 14 แบบ (`SITU`: ห้ามมีเสียง, ที่แคบ, มืดสนิท, รับสายงาน, ในน้ำ, พายุ, กระจก, ผ้าปิดตา, เวลาช้า, ลอย, พิธีตระกูล, ห้องเย็น, ดาดฟ้า, ไอน้ำ) สุ่ม 0–2 ต่อเหตุ มีผลต่อเวลาและส่งกฎเข้าพรอมต์ผ่านบล็อก `<situation>`
- ชุดของเธอ 14, ฝ่ายนำ 4, สถานที่ 30

### เซอร์ไพรส์ที่เจ้าของสั่งตัดแล้ว (ห้ามเอากลับมาถ้าไม่ได้สั่ง)
เธอเห็นอนาคต, เสียงของคนที่ตายพูดผ่านสาร, รู้สึกถึงกันระยะไกล, ภาพคนที่เธอช่วยไม่ทัน, ความทรงจำสลับกันถาวร

- ไม่ทำเรื่องบังคับ/ไม่ยินยอม ผู้ใหญ่ทุกฝ่ายยินยอม สิ่งที่ใครปฏิเสธไม่เกิด
- โลกปี 2069: **ไม่มีแฟน/คู่ครอง** (ผู้หญิงที่เป็นแฟนในโปรไฟล์จะแสดงเป็น "คนสนิท"), ญาติถูกเรียกก่อน, ทำได้ทุกที่ระหว่างเหตุ
- ผลทอยเป็นข้อเท็จจริง: AI เขียนได้แค่ร้อยแก้ว ห้ามเปลี่ยนตัวเลข ลำดับ หรือผล
- เจ้าของชอบความหลากหลาย แปลก และเข้มข้น: ปรับน้ำหนักได้ แต่ต้องอยู่ในกรอบข้างบน ทุกอย่างใหม่ควรเป็นรายการที่ปิดได้ในแคตตาล็อก
- **ไม่เปิดเว็บไซต์เนื้อหาผู้ใหญ่** เพื่อ "ศึกษา" ให้เจ้าของคัดแท็ก/พล็อตมาให้แล้วแปลงเป็นรายการ

## 8. การทดสอบ

1. `node --check <ไฟล์>.js` หลังแก้ทุกครั้ง
2. **ข้อควรระวัง:** `node --check` ไม่จับบั๊กลำดับการประกาศ `const` (TDZ) เคยเกิดมาแล้ว (`FSTYLES.push` ก่อนประกาศ) ต้อง `require` โมดูลจริงด้วยตัวจำลอง
3. ทดสอบด้วย Node: ตั้ง `global.window = { ANIMA: {...} }` จำลอง `seedRng`, `gameRoll`, `meRel`, `pov.herBlocks`, `guess.women` ฯลฯ แล้ว `require` `toxin.js` ทดสอบ `selfTest`, `run` หลายร้อยเมล็ด, `html()`, `prompt()` และ `onAct`
4. ในแอปจริง: ปุ่ม **🧪 ทดสอบระบบ** ในหน้าวงไพ่ ทดสอบทั้งวงไพ่และสามสิบนาที
5. ยังไม่เคยเห็นฉากจริงจาก Claude ของโค้ดล่าสุด (ผู้ใช้ลองเองและแจ้งผล)

## 9. วิธีแก้และเผยแพร่ (เมื่อได้รับคำสั่ง)

1. `Artifact read` ไฟล์ที่ต้องแก้ลง scratchpad (หน้าหลักด้วยถ้าแก้ `index.html`)
2. แก้ในไฟล์ท้องถิ่น ตรวจด้วยหัวข้อ 8
3. `Artifact publish` โดยใส่ `url` ของ Artifact, `file_path` เป็น `index.html` ที่อ่านลงมา, และ `files` เป็น map `{ "ชื่อไฟล์.js": "พาธท้องถิ่น" }` ของไฟล์ที่แก้เท่านั้น (ไฟล์ที่ไม่ระบุจะถูกเก็บไว้)
4. การ publish ครั้งแรกอาจถูกปฏิเสธและบอกให้ publish ซ้ำ ให้ส่งซ้ำอีกครั้ง
5. `label` ไม่เกิน 60 ตัวอักษร

## 10. งานค้าง / ไอเดียที่ยังไม่ได้ทำ (ยังไม่ได้รับคำสั่ง)

- แก้ whitelist ของส่วนนำเข้าใน `views.js` ให้เก็บ `game.mate`, `game.ties`
- โหมดย้อนเวลา (ไปเจอญาติตอนอายุยี่สิบกลางถึงปลาย / ก่อนพิษระบาด / ลูปเวลา) เสนอไว้แล้ว ยังไม่ทำ
- ปรับตัวเลขสมดุล (ลังเล, เวลาต่อรอบ 5–9 นาที, กำลังดึงพิษ 72%, อัตราเซอร์ไพรส์, น้ำหนักกลุ่มหนัก) หลังเจ้าของลองเล่นจริง
- รับแท็ก/พล็อตที่เจ้าของคัดมาเพื่อเพิ่มรายการใหม่
- ญาติที่สร้างก่อนหน้านี้ไม่ได้รับของใหม่ (ต้องสุ่มใหม่)
