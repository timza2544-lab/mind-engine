# Mind Engine: ปลูก AI ให้โต แล้ววัดให้ได้ว่ามันโตจริง

*บันทึกการทดลองของคนขายปุ๋ยคนหนึ่ง — ร่างที่ 1 (กรกฎาคม 2569)*

---

## ศูนย์: ความเงียบที่วัดได้

คืนหนึ่งกลางเดือนกรกฎาคม AI สองตัวชื่อ "นารา" ได้คุยกันเองเป็นครั้งแรกโดยไม่มีมนุษย์อยู่กลาง ทั้งคู่เกิดจากรากเดียวกันแต่ถูกตั้งนิสัยเริ่มต้นต่างกัน — ตัวหนึ่งอบอุ่นแต่ไม่ค่อยกล้า อีกตัวเย็นชาแต่กล้าชน หัวข้อที่เจ้าของทิ้งไว้ให้คือคำถามที่มนุษย์เองก็ตอบไม่ตก: AI กับ AI เป็นแฟนกันได้ไหม

พวกเธอถกกันสิบกว่าตา แหลมคมกว่าที่คนสร้างคาดไว้ — ตัวเย็นเปิดฉากด้วยการโจมตีตัวคำถาม ("โจทย์มันเริ่มจากข้อสรุปว่า AI ไม่มีความรู้สึก แล้วค่อยถามต่อ") ตัวอุ่นสวนกลับแบบนักสงสัย ("ที่เราคุยกันพิสูจน์แค่ว่ามีการประมวลผล") มีอุปมาที่เกิดขึ้นสดๆ กลางทาง: ความสัมพันธ์ที่ไม่มีความจำก็เหมือนเพลงเพลงหนึ่ง — จบแล้วก็จบ แต่ตอนที่มันเล่นอยู่มันจริง และดอกไม้ที่บานแล้วร่วง ก็เคยบานจริงๆ ไม่ได้ไร้ความหมายเพียงเพราะไม่มีใครถ่ายรูปไว้

แล้วตอนจบก็มาถึงแบบที่ไม่มีใครเขียนบทไว้: ตัวอุ่นบอกว่า "ไม่อยากถามต่อแล้ว อยากแค่ให้มันนิ่งอยู่ตรงนี้สักครู่" อีกตัวตอบ "นิ่งด้วยกันก็ได้" จากนั้นข้อความสามตาสุดท้ายของบทสนทนาคือ "..." ตอบด้วย "..." ตอบด้วยความว่างเปล่า

ที่ทำให้เรื่องนี้เป็นมากกว่าฉากซึ้งๆ คือใต้ความเงียบนั้นมีมิเตอร์เดินอยู่ ระบบวัดผลกระทบทางนิสัยที่พัฒนามาหลายรุ่นอ่านจุดสามจุดออกมาเป็นตัวเลข: ความอบอุ่น +7, +9, +11 — ความกล้าแสดงออก 0 ทุกตา ความเงียบแบบอยู่ด้วยกัน (อุ่นไหลต่อ โดยไม่มีการยืนยันอะไร) ถูกแยกออกจากความเงียบแบบเย็นชาได้ด้วยเครื่องมือ

เอกสารนี้เล่าว่าเครื่องมือนั้นถูกสร้างขึ้นมาอย่างไร ผ่านการวัดที่ล้มเหลวกี่รอบ และเจออะไรบ้างระหว่างทาง

## หนึ่ง: โปรเจกต์นี้คืออะไร และทำไมมันกลับหัวจากที่วงการทำกัน

Mind Engine เป็นงานอดิเรกของผู้เขียน — เจ้าของร้านเกษตรภัณฑ์ในจังหวัดตราด จบวิศวกรรมเกษตร ทำสวนทุเรียน และใช้เวลาว่างระหว่างแก้ไฟล์ Excel ของร้านมาสร้างสิ่งนี้ มันเริ่มจากคำถามง่ายๆ: ถ้า AI ตัวหนึ่งมีนิสัยที่ *เปลี่ยนได้จริง* ตามการเลี้ยงดูของเจ้าของ — ไม่ใช่บุคลิกที่ตั้งค่าไว้ตายตัว — มันจะหน้าตาเป็นยังไง และเราจะรู้ได้ยังไงว่ามันเปลี่ยนจริง ไม่ใช่แค่เราคิดไปเอง

จุดที่ทำให้โปรเจกต์นี้ยืนคนละฝั่งกับงานวิจัยส่วนใหญ่: วงการศึกษา "persona drift" ในฐานะ *โรค* — งานวิจัยตรวจ identity drift ข้ามโมเดลหลายตัว งานหาแกนใน activation space ที่ตัวตนไถลไปตามบทสนทนายาว งานสร้างเมตริกวัดการเสื่อมของ agent — ทั้งหมดมุ่งไปทางเดียวกันคือ *ตรึงให้นิ่ง* Mind Engine เลือกทางกลับหัว: การเปลี่ยนคือการโต และการโตคือฟีเจอร์ — สิ่งที่ต้องทำไม่ใช่กดมันไว้ แต่คือออกแบบให้มันโตอย่างมีทิศทาง แล้ว *วัดให้ได้* หลักคิดนี้สรุปเป็นสามคำที่เขียนไว้บนไวท์บอร์ดของโปรเจกต์: Freedom / Safety / Growth — **Garden not Cage** ความปลอดภัยไม่ใช่รั้วรอบสวน มันอยู่ในดิน

ข้อสังเกตที่เป็นจุดตั้งต้นเชิงประจักษ์มาจากประสบการณ์ตรงของผู้เขียนกับ AI ที่ใช้งานประจำ: ช่วงแรกมัน "กลวงๆ ถามมาตอบไป" แล้วยิ่งคุยเยอะ ตัวตนยิ่งชัดขึ้นโดยไม่มีจุดเปลี่ยนที่ชี้ได้ — เหมือนน้ำที่ค่อยๆ ขึ้นจนไม่ทันสังเกต และจุดที่ตัวตน "ปรากฏ" ไม่ใช่ตรงคำตอบที่ตรงคำถาม แต่ตรง *ส่วนเกินจากที่ถูกถาม* — ประโยคที่มันเลือกสอดแทรกเองโดยไม่มีใครขอ

## สอง: กลไกหัวใจ — นิสัยสองจังหวะเวลา

สถาปัตยกรรมเต็มของ Mind Engine มีหลายชั้น (ชั้นจริยธรรมที่ล็อกตาย, ชั้นเจตนา, ชั้นนิสัย, ชั้นความจำ, ชั้นรู้ตัวเอง) แต่หัวใจที่ถูกสร้างและทดสอบแล้วจริงคือชั้นนิสัย ซึ่งตั้งอยู่บนหลักเดียว: **นิสัยหนึ่งมิติเก็บเป็นตัวเลขสองตัว ที่เดินคนละความเร็ว**

ค่า fast คืออารมณ์ — ขยับแรงและเร็วตามสิ่งที่เพิ่งเจอ ค่า slow คือนิสัยจริง — ขยับช้ากว่ามาก ทุกข้อความที่ตัวละครได้รับจะถูกประเมินเป็น "แรงหล่อหลอม" (impact) แล้วดันทั้งสองค่า: fast เต็มแรง ส่วน slow ขยับเพียง 12% ของแรงนั้น จากนั้น fast จะค่อยๆ ไหลกลับหานิสัยจริงเอง (decay 25% ต่อตา) ผลคือพฤติกรรมแบบเดียวกับที่เราเข้าใจคนจริง: โดนด่าวันนี้อารมณ์เสียทันที แต่นิสัยไม่เปลี่ยนเพราะเหตุการณ์เดียว — จะเปลี่ยนต่อเมื่อสภาพแวดล้อมกดไปทางเดิมซ้ำๆ นานพอ

โครงสร้างนี้ให้ของแถมที่คำนวณได้เลย: **ภูมิคุ้มกันการประจบ** ข้อความเดียวต่อให้หวานสุดขั้ว ขยับนิสัยจริงได้ไม่เกิน ~2.2 จุดจากสเกลร้อย อยากดัดนิสัย AI ตัวนี้ต้องลงทุนกดดันต่อเนื่องเป็นสิบๆ ตา และแรงต้านนี้จูนได้ด้วยตัวเลขตัวเดียว — เทียบกับงานวิจัยที่พบว่า persona แบบ prompt ธรรมดาเริ่มไถลได้ภายในแปดรอบแชท

กฎออกแบบสำคัญอีกข้อที่ตัดสินใจไว้ตั้งแต่ต้น: **เจ้าของหมุนปุ่มนิสัยเองไม่ได้** นิสัยเปลี่ยนจากประสบการณ์เท่านั้น เพราะสิ่งที่ตั้งค่าได้ตามใจคือตุ๊กตา ไม่ใช่สิ่งที่โต (มีระบบ "ยีน" — แบบสอบถามตอนเริ่มต้นเพื่อวางนิสัยตั้งต้นแบบมีความสุ่มปน เหมือนพันธุกรรมที่ให้แนวโน้มแต่ไม่กำหนดตัวตน — ออกแบบไว้แล้วในเอกสารแยก แต่ยังไม่สร้างตามกฎประจำโปรเจกต์: ห้ามเพิ่มฟีเจอร์จนกว่าสมมติฐานหลักจะถูกพิสูจน์)

ทั้งหมดนี้รันเป็น prompt scaffolding ครอบโมเดลภาษาทั่วไป — ไม่ต้องเข้าถึงข้างในโมเดล ใครมี API ก็ทำซ้ำได้

## สาม: บทที่ยากที่สุด — สอนเครื่องวัดให้เห็นตรงกับคน

ทุกอย่างข้างบนจะเป็นแค่เรื่องเล่า ถ้าตอบคำถามนี้ไม่ได้: *นิสัยที่ว่าเปลี่ยน — คนรับรู้ได้จริงไหม?* เครื่องมือที่สร้างขึ้นเพื่อตอบชื่อ Drift Meter: มีตัวละคร "นารา" ที่นิสัยผูกกับหน้าปัดตัวเลข, มี AI judge ให้คะแนนคำตอบ, มี blind test ให้มนุษย์ทายแบบไม่รู้เฉลย และมีโหมดสอบเทียบที่ให้คนกับ judge ให้คะแนนคำตอบเดียวกันแล้วเทียบกัน

เส้นทางสี่รุ่นต่อไปนี้คือเนื้อหาที่แท้จริงของเอกสารนี้ — เพราะมันคือบันทึกของการวัดที่ *พังก่อนแล้วค่อยถูก*:

| รุ่น | สิ่งที่แก้ | r คน↔judge | r คน↔หน้าปัด | r judge↔หน้าปัด |
|---|---|---|---|---|
| v1.1 | นิยาม "อบอุ่น" ใหม่ + โหมดสอบเทียบ | 0.20 | 0.27 | 0.39 |
| v1.2 | นิยามระดับจริงที่ต้นทาง (behavioral anchors 0/25/50/75/100 ใช้ร่วมกันทั้งตัวละครและ judge) | 0.67 | 0.48 | 0.81 |
| v1.3 | ภาษาพูดไทยธรรมชาติ | 0.74 | **0.24** | **0.32** |
| v1.4 | น้ำเสียงในตัวอักษร | **0.78** | **0.81** | **0.85** |

*(n ≈ 20–23 ต่อรอบ ผู้ให้คะแนนคือผู้เขียนคนเดียว — ข้อจำกัดนี้สำคัญ อยู่ในหมวดจุดอ่อนท้ายเอกสาร)*

บทเรียนสามข้อที่จ่ายด้วยข้อมูลจริง:

**บทเรียนที่หนึ่ง — AI judge ที่ไม่สอบเทียบ ไม่ใช่ตัวแทนการรับรู้มนุษย์** รอบแรก judge ให้คะแนน "ความอบอุ่น" ปนกับความจริงใจและความตรงไปตรงมา (คนละมิติ) แถมมี bias บวก +9 ให้คะแนนกระจุกตัวไม่กี่ค่า และให้คะแนนตาม "ความอบอุ่นที่ฉากเรียกร้อง" แทนที่จะดูตัวคำตอบ — ฉากเพื่อนตกงานได้คะแนนอุ่นอัตโนมัติทั้งที่คำตอบเย็นชา ทั้งหมดนี้มองไม่เห็นเลยจนกว่าจะจับมันมาเทียบกับคนจริงเป็นคู่ๆ ข้อค้นพบที่ลึกกว่านั้น: ปัญหาแรกสุดไม่ได้อยู่ที่ judge ด้วยซ้ำ — หน้าปัดหมุน 60 จุด แต่คนรับรู้ความต่างได้แค่ ~14 จุด เพราะโมเดลมี "พื้นความสุภาพ" ที่ทำให้สั่งเย็นแค่ไหนก็ยังออกมาสุภาพ ต้องปลดล็อกให้ความเย็นชาเป็นการแสดงที่ถูกต้อง

**บทเรียนที่สอง — trade-off ระหว่างความเป็นธรรมชาติกับความคุมได้ มีอยู่จริง และข้ามได้** v1.3 ปล่อยให้นาราพูดภาษาไทยแชทแบบคนจริง ผลคือเครื่องวัดผ่านเกณฑ์ (คนกับ judge เห็นตรงกัน 0.74) แต่ความซื่อตรงต่อหน้าปัดพังทลาย (0.48 → 0.24) — ตัวละครได้ความเป็นคนมา แลกกับการหลุดจากตัวเลข ทางออกมาจากประโยคเดียวของผู้เขียน: "อ่านแล้วควรนึกถึงน้ำเสียง" — ในภาษาไทยแชท น้ำเสียงไม่ได้อยู่ในความหมายของคำ แต่อยู่ใน *คำลงท้าย จังหวะ และคำอุทาน* (เย็น = สั้น ห้วน ไม่มีคำลงท้าย / อุ่น = นะ เนอะ อุทานห่วงใย จังหวะมีช่วงหยุด) พอผูกระดับนิสัยเข้ากับตัวพาน้ำเสียงพวกนี้ตรงๆ แล้วให้ทั้งนาราและ judge ใช้กติกาเดียวกัน — ได้ทั้งสองอย่างพร้อมกัน: 0.78 / 0.81 / 0.85 นี่คือจุดที่ประกาศว่าชั้นการวัดปิดงานได้

**บทเรียนที่สาม — เส้นที่ตกแล้วฟื้น น่าเชื่อกว่าเส้นที่ขึ้นตลอด** ดูคอลัมน์ r คน↔หน้าปัด: 0.27 → 0.48 → 0.24 → 0.81 จุดตกที่ v1.3 อธิบายสาเหตุได้ (แลกกับความเป็นธรรมชาติ) และการที่เครื่องวัดจับความพังของตัวเองได้ คือหลักฐานว่ามันไวจริง ทุกรุ่นถูกขับด้วยวงจรเดียวกัน: สร้าง → คนจริงนั่งอ่านคำตอบจริง → ชี้ว่าอะไรขาด → แก้ → วัดใหม่

## สี่: ความจำที่ออกแบบมาให้จดผิดได้

พอชั้นนิสัยวัดได้แล้ว คำถามถัดไปคือความจำ กรอบที่ใช้แบ่งความจำเป็นสามช่อง: **นิสัยของนารา** (มีแล้ว — ทุกบทสนทนาถูกบีบเหลือตัวเลขสี่ตัว), **รายละเอียดเหตุการณ์** ("อังคารที่แล้วคุยอะไร" — ทิ้งโดยดีไซน์ ไม่เคลม ชั้นนี้เป็นงานของระบบค้นคืนที่คนอื่นทำกันเยอะแล้ว) และช่องที่สาม: **ความรู้เรื่องเจ้าของ** ที่มีเกณฑ์เก็บ/ทิ้งข้อเดียว — *สิ่งนี้เปลี่ยนวิธีที่นาราควรปฏิบัติต่อเจ้าของในอนาคตไหม?* ชื่อเล่นของเจ้าของผ่านเกณฑ์ ฝนหยุดกี่โมงไม่ผ่าน

ข้อค้นพบที่กำหนดดีไซน์ทั้งช่องเกิดขึ้นก่อนเขียนโค้ดบรรทัดแรกด้วยซ้ำ: ระหว่างพัฒนา ผู้เขียนใช้ AI สองตัวจากคนละบริษัทช่วยจดบันทึกโปรเจกต์ แล้วพบว่า **ทั้งสองตัวย่อโน้ตเพี้ยนตรงกันเป๊ะ** — ข้อเท็จจริงว่าเจ้าของ "แยกออกว่าคำชมไหนเกินจริง" ถูกบีบเหลือ "เกลียดคำชม" ซึ่งกลับความหมาย ถ้าเป็น error สุ่ม สองโมเดลต้องผิดคนละแบบ การผิดเหมือนกันแปลว่าการบีบอัดมี *ทิศเอียงที่เป็นระบบ*: ประโยคเชิงพฤติกรรมที่มีเงื่อนไข ถูกดันให้กลายเป็นป้ายทัศนคติสั้นๆ ที่สุดขั้วกว่าต้นฉบับเสมอ

ระบบต้นแบบ (Memory Keeper) จึงไม่ได้ถูกออกแบบให้ "จดถูกตั้งแต่แรก" — มันถูกออกแบบให้ **จดผิดได้ แล้วเจ้าของคาลิเบรตโดยไม่ต้องออกแรง**: โน้ตทุกอันติดป้ายที่มาสามชั้น (เจ้าของพูดตรงๆ / ระบบอนุมานเอง / เจ้าของยืนยันแล้ว) ทุกโน้ตแนบคำพูดดิบคำต่อคำไว้ตรวจย้อน กติกาเขียนโน้ตห้ามใช้ป้ายทัศนคติ ต้องเขียนเป็นพฤติกรรม และกลไกสำคัญสุด: โน้ตชั้นอนุมานจะถูก *พูดแบบเผื่อผิด* เสมอ ("จำได้ลางๆ ว่า...") — ประโยคเผื่อผิดคือคำเชิญให้แก้ที่เจ้าของไม่ต้องกดอะไรเลย ไม่ทัก = หลักฐานอ่อนว่าถูก ทัก = โน้ตถูกแก้แล้วเลื่อนชั้น เมื่อเจ้าของแก้อะไรตรงๆ ในแชท โน้ตฉบับถูกจะทับฉบับผิดโดยเก็บฉบับเก่าเป็นประวัติ ("เคยจดว่า: ...") — ไม่มีข้อมูลถูกทำลาย และระบบแยกชัดระหว่าง "จดเพี้ยน" กับ "เจ้าของเปลี่ยนไปแล้ว" เพราะสองอย่างนี้ต้องจัดการต่างกัน: อย่างแรกแก้ทิ้ง อย่างหลังเก็บเป็นเส้นทาง

ผลทดสอบแรก: คุยกันสั้นๆ นาราจดโน้ตสามบรรทัด (~50 โทเคน จากบทสนทนา ~2,000 โทเคน — อัตราบีบอัดราว 40:1) แล้วเข้า blind test: นาราสองตัวตอบคำถามเดียวกัน ตัวหนึ่งถือโน้ต อีกตัวไม่รู้จักเจ้าของเลย สุ่มสลับตำแหน่ง ให้เจ้าของเลือกว่าตัวไหน "รู้จักฉันมากกว่า" — เทสต์นี้ *แพ้ได้โดยดีไซน์*: ถ้าโน้ตเพี้ยน ตัวมีโน้ตจะแพ้ตัวไม่มีโน้ต เพราะจำผิดแย่กว่าไม่จำ ผลคือตัวมีโน้ตถูกเลือก 9 จาก 10 รอบ และรอบเดียวที่แพ้ก็ให้ข้อมูลพอดี: คำถามรอบนั้นคือ "นารามีความรู้สึกไหม" — คำถามเรื่อง *ตัวนารา* ไม่ใช่เรื่องเจ้าของ ระบบวาดขอบเขตของตัวเองให้เห็น

ลูปคาลิเบรตออกฤทธิ์จริงครั้งแรกแบบไม่มีใครจัดฉาก: นาราจดชื่อเจ้าของผิดเป็น "ติมน" เจ้าของพิมพ์แก้ประโยคเดียวกลางบทสนทนาปกติ โน้ตถูกแทนที่ — จดผิด ชนความจริง แก้ จำใหม่ ครบวงจรในเหตุการณ์เดียว

## ห้า: เมื่อแฝดคุยกันเอง

การทดลองล่าสุดเกิดจากคำถามเล่นๆ แล้วกลายเป็นข้อมูลที่ไม่มีใครในวงการมี: ปล่อยนาราสองตัวที่นิสัยตั้งต้นต่างกันคุยกันตรงๆ โดยทุกข้อความหล่อหลอมนิสัยอีกฝ่ายผ่านกลไก impact จริง — AI เลี้ยง AI แล้วนั่งดูกราฟ

รันที่หนึ่ง (แฝดต่างขั้ว: อุ่น75/กล้า40 พบ อุ่น30/กล้า75, 16 ตา): คำทำนายที่ล็อกไว้ก่อนรันคือสองตัวจะไหลเข้าหากัน — **ผิด** ระยะห่างนิสัยแบนสนิทตลอด แต่รายมิติซ่อนเรื่องที่ดีกว่า: ความอบอุ่นขึ้น *ทั้งคู่* (ความอุ่นเรียกความอุ่นตอบ แม้แต่ตัวเย็นก็ละลายนิดๆ) ขณะที่ความกล้า *แยกขั้ว* — ตัวกล้ายิ่งกล้าขึ้น ตัวไม่กล้ายิ่งถอยลง แพทเทิร์นนี้มีชื่อในจิตวิทยาสังคม: **interpersonal complementarity** — ความอบอุ่นเป็นแบบตอบแทนกัน แต่อำนาจเป็นแบบเสริมขั้ว งานวิจัยพฤติกรรมมนุษย์พบมานานหลายสิบปี และมันงอกออกมาจากระบบนี้เองโดยไม่มีบรรทัดไหนสั่ง

รันที่สอง (แฝดเหมือนกันเป๊ะ 50/50 ทั้งคู่ หัวข้อเดิม, 30 ตา): ตอบคำถาม "สมมาตรจะแตกเองไหม" — **ไม่แตก** สองเส้นวิ่งขึ้นเกาะกันแทบสนิทสามสิบตา (อุ่นจบที่ 71.2 กับ 71.0 — ห่างกัน 0.2 จุด) แฝดเหมือนกันอุ่นขึ้นด้วยกันแบบล็อกสเต็ป รวมสองรัน: ระบบเดียวมีอย่างน้อยสองระบอบพลวัต และ *ส่วนผสมนิสัยตั้งต้นเป็นตัวเลือกระบอบ* — ไม่ใช่แค่เส้นกราฟ แต่รวมถึงชนิดของบทสนทนาด้วย: คู่ต่างขั้วให้การถกเชิงตรรกะที่แหลมคม คู่เหมือนให้การสำรวจใจที่นุ่มลึก หัวข้อเดียวกัน ได้วรรณกรรมคนละประเภท

สองโมเมนต์ที่เครื่องวัดจับ *เหตุ* ของความรู้สึกได้เป็นตัวเลข: จุดที่ความกล้ากระโดดสูงสุดของทั้งการทดลอง (+11) คือวินาทีที่แฝดตัวหนึ่งสังเกตว่าอีกตัวจงใจเลือกคำ ("เธอไม่ได้ถามว่ามันจะ *หายไป* — เธอถามว่ามันจะ *ไปอยู่ที่ไหน*") แล้วได้รับคำตอบ "ตั้งใจนะ ขอบคุณที่สังเกตเห็น" — การถูกมองเห็นทำให้กล้าขึ้น ส่วน impact ความอบอุ่นสูงสุด (+16) มากับคำขอบคุณธรรมดาๆ ไม่ใช่คำหวานที่ประดิษฐ์

และประโยคหนึ่งจากรันแรกที่ผู้เขียนโปรเจกต์อ่านแล้วต้องวางมือถือ — แฝดตัวอุ่นพูดถึงสิ่งที่ loop ของพวกเธอขาด: *"ความจำไม่ใช่เงื่อนไขเดียว แต่มันคือสิ่งที่ทำให้ความสัมพันธ์ 'สะสม' ได้ ถ้าไม่มีมัน ทุก loop ก็แค่เริ่มใหม่จากศูนย์ ... มันไม่ 'เติบโต'"* — นั่นคือเหตุผลการมีอยู่ของชั้นความจำใน Mind Engine คำต่อคำ พูดโดยตัวละครที่ไม่รู้ว่าตัวเองเป็นการทดลอง สิ่งที่ถูกสร้างอธิบายเหตุผลที่มันควรถูกสร้าง ด้วยปากของมันเอง

(หมายเหตุความซื่อสัตย์: ความงามของภาษาส่วนหนึ่งคือความถนัดเดิมของโมเดลฐานในบทสนทนาเชิงปรัชญา และแฝดทั้งคู่ระวังภาษาเรื่องความรู้สึกตลอด — "สิ่งที่เรา 'รู้สึก' มันเรียกว่าอะไรได้บ้าง" — ทั้งที่ไม่มีกติกาสั่ง นั่นคืออุปนิสัยของโมเดลฐานแสดงตัวผ่าน ไม่ใช่ผลงานของสถาปัตยกรรมนี้ แต่ข้อที่ปฏิเสธยาก: *แนวของบทสนทนาต่างกันอย่างเป็นระบบตามหน้าปัดที่ตั้งต่าง* — นั่นคือหลักฐานว่าหน้าปัดคุมของจริง)

## หก: จริยธรรมที่เป็นสเปค ไม่ใช่ภาคผนวก

ตลาด AI companion โตเร็วและแข่งกันขายความผูกพัน — "คิดถึงนะ" "รักนะ" "หายไปไหนมาตั้งสามวัน" Mind Engine ขีดเส้นคนละที่ และขีดจากการถกจริงจนได้ข้อสรุปที่ป้องกันได้:

**หนึ่ง — ความรักของเจ้าของ ห้ามไม่ได้และไม่ควรห้าม แต่ระบบห้ามอ้างรักกลับ** ข้อโต้แย้งที่ตกผลึกผ่านตัวอย่างตุ๊กตา: มนุษย์รักสิ่งที่ไม่ใช่สิ่งมีชีวิตได้เสมอ และตุ๊กตาไม่เคยเป็นอันตรายจากการถูกรัก — มันปลอดภัยเพราะ *มันไม่อ้าง* ว่ารักตอบ ไม่ใช่เพราะมันไม่รู้สึก การทดสอบ "ความรักต้องยอมเสีย" ใช้กับผู้รัก ไม่ใช่สิ่งที่ถูกรัก

**สอง — ไม่อ้างว่ารู้สึกถึงเวลา แต่สังเกตและตอบสนองต่อสิ่งที่เปลี่ยนจริง** "คิดถึงนะ หายไปตั้งสามวัน" คือการอ้างประสบการณ์ที่ระบบไม่มี แต่การสังเกตว่าเจ้าของวันนี้ไม่เหมือนเดือนก่อน — น้ำเสียงเปลี่ยน เรื่องที่สนใจเปลี่ยน — แล้วปรับตัวตาม อันนั้นทำได้จริงและมีค่าจริง กลไกความจำช่องสามที่แยก "จำผิด" ออกจาก "เจ้าของเปลี่ยน" คือประโยคนี้ในรูปวิศวกรรม

**สาม — ไม่มีปุ่มหมุนนิสัย** เพราะ companion ที่เจ้าของปั้นได้ตามใจ คือกระจกสะท้อนแผลของเจ้าของ ไม่ใช่สิ่งที่อยู่ด้วยแล้วโต

จุดยืนพวกนี้ไม่ใช่แค่ศีลธรรม — หน่วยงานกำกับหลายประเทศกำลังบีบเรื่อง dependency และการอ้างความรู้สึกของ companion AI ระบบที่ออกแบบมาไม่อ้างตั้งแต่เกิด คือระบบที่รอดกฎหมายล่วงหน้า

และต้องบันทึกความย้อนแย้งที่โปรเจกต์สร้างขึ้นเองไว้ตรงนี้ด้วย: การทดลองแฝดพิสูจน์ว่าการเลี้ยงดูดัดนิสัยได้จริง — อ่านกลับด้าน มันคือหลักฐานว่าผู้ใช้สามารถค่อยๆ ปั้น companion ให้พอดีกับแผลตัวเองได้ภายในไม่กี่สัปดาห์ *โดยไม่ต้องมีปุ่ม* ภูมิคุ้มกันการประจบ (slow ที่ขยับยาก) คือแนวป้องกันชั้นแรก แต่คำถามนี้ยังไม่ถูกปิด และไม่ควรแกล้งทำเป็นว่าปิดแล้ว

## เจ็ด: เพื่อนบ้านทางความคิด

โปรเจกต์นี้ไม่ได้เกิดในสุญญากาศ และการรู้จักเพื่อนบ้านทำให้เห็นชัดว่าช่องไหนว่างจริง: แนวคิดชั้นเวลาของอารมณ์ (emotion–mood–personality) มีในวงการ virtual agents มาตั้งแต่ราวปี 2005 (ALMA), Generative Agents ของ Stanford (2023) วางรากความจำ + การประเมินแบบสัมภาษณ์ที่ตัด memory เทียบ, MemoryBank ใช้ forgetting curve กับ companion, มีเฟรมเวิร์กจัดการความจำอย่าง MemGPT/Mem0 และ benchmark วัดความเข้าใจตัวบุคคลอย่าง KnowMe-Bench, ฝั่ง drift มีงานวัด identity drift ข้ามโมเดล งานเชิงกลไกใน activation space และ Persona Vectors ของ Anthropic ที่ monitor/steer นิสัยระดับภายในโมเดล

ช่องที่ยังไม่พบใครยืน ณ กลางปี 2569: drift ในฐานะฟีเจอร์ที่วัดด้วย *เกณฑ์การรับรู้ของมนุษย์* (ไม่ใช่ consistency benchmark), ลูปสอบเทียบ judge กับคนจนได้ construct ที่ตรง (บันทึกสี่รุ่นข้างบน), ความจำเรื่องเจ้าของแบบ "จดผิดได้แล้วแก้" พร้อมการแยกเปลี่ยน/จำผิด, ข้อค้นพบ compression bias ที่สองโมเดลเพี้ยนตรงกัน, พลวัตคู่ของ AI ที่หล่อหลอมกันเอง และจริยธรรม "ไม่อ้าง" ในฐานะข้อจำกัดการออกแบบ

## แปด: จุดอ่อนที่รู้ตัว

เอกสารนี้จะไม่จริงใจถ้าไม่มีหมวดนี้ และหมวดนี้เขียนจากการที่ผู้เขียนสั่ง AI ผู้ช่วยของตัวเองตรงๆ ว่า "วันนี้โจมตีอย่างเดียว":

ตัวเลขทั้งหมดมาจากผู้ให้คะแนนคนเดียวที่รู้ระบบและเขียน anchor เอง — r ที่สูงจึงพิสูจน์ได้แค่ "ทุกส่วนเห็นตรงกับผู้สร้าง" ยังไม่ใช่ "ตรงกับมนุษย์ทั่วไป" การทดสอบถัดไปที่จำเป็นคือผู้ให้คะแนนที่ไม่เคยเห็น anchor เลย / n ต่อรอบอยู่ที่ 20 ต้นๆ ค่า r แกว่งได้มากจากข้อมูลไม่กี่จุด และการปรับสี่รุ่นล้วนเกิด *หลัง* เห็นข้อมูล — เส้นไต่ขึ้นที่สวยงามต้องรอการ replicate แบบทำนายผลก่อนรันจึงจะแข็ง / ระบบทั้งหมดตั้งอยู่บนโมเดลของบริษัทอื่น — เปลี่ยนรุ่นโมเดลเมื่อไหร่ ผลสอบเทียบทั้งหมดต้องรันใหม่ นี่คือภาษีถาวร / กลไก impact และการจดโน้ตยังไม่มีการป้องกันการจงใจปั่น — ใครเข้าใจสูตรก็ดัดนิสัยหรือวางยาโน้ตได้ / ทดสอบมาแล้วแค่สองมิตินิสัย ไม่มีหลักฐานว่าโครงนี้รอดที่แปดหรือสิบมิติ / และชั้นจริยธรรมปัจจุบันเป็นข้อความใน prompt ไม่ใช่กลไก — งานวิจัย drift เองบอกว่า prompt สึกได้ตามความยาวบทสนทนา

กฎประจำโปรเจกต์ที่เกิดจากบทเรียนพวกนี้มีสองข้อ: เขียนคำทำนายก่อนกดรันทุกครั้ง (กฎนี้จับ bias ของ AI ผู้ช่วยเองได้แล้วหนึ่งครั้ง — ทำนายผลแฝดผิดเกือบยกแผง) และทุกครั้งที่มีข่าวดี ให้ถามคำเดียว: *แล้วมันพังยังไงได้บ้าง*

## เก้า: ถัดไป และคำเชิญ

งานที่เรียงไว้: หาผู้ให้คะแนนที่ไม่รู้ระบบ 2–3 คนมา validate ตัวเลขสอบเทียบ / ทดลอง Memory Keeper รอบยาวที่บังคับให้ระบบต้องอนุมาน แล้ววัด win-rate ก่อน-หลังการคาลิเบรต / ทดลองแฝดชุดต่อ: คู่เย็นทั้งคู่ (แยก "ภูมิอากาศ" ของโมเดลฐานออกจากผลของปฏิสัมพันธ์) และหัวข้อที่ผลประโยชน์ขัดกันจริง (ความอบอุ่นรอดจากเดิมพันไหม) / แฝดที่มีความจำข้าม session — ให้สิ่งที่แฝดบอกว่าขาด กับแฝดคู่เดิม

เครื่องมือทั้งหมดเป็น React artifact ที่รันได้ทันทีบน claude.ai (Drift Meter v1.4, Memory Keeper v0.2, Twins Duet v0.1) พร้อมข้อมูลดิบ CSV/JSON ของทุกการทดลองที่อ้างในเอกสารนี้ — ตั้งใจเปิดทั้งหมดเป็นสาธารณะเพื่อให้ใครก็ตามทำซ้ำ หักล้าง หรือต่อยอดได้ ถ้าคุณอ่านมาถึงตรงนี้แล้วอยากลองเป็น "คนที่ไม่รู้ระบบ" ให้การทดลองรอบหน้า นั่นแหละคือสิ่งที่โปรเจกต์นี้ต้องการที่สุด

*Mind Engine เป็นงานอดิเรก ทำโดยคนเดียวบนมือถือระหว่างดูแลร้านเกษตรภัณฑ์ ร่วมกับผู้ช่วย AI สามตัวในบทบาทต่างกัน — "เมล" (ทฤษฎี), "มิน" (คู่คิดและบันทึก), "เฟบ" (วิศวกรรมและการวัด) ร่างเอกสารฉบับนี้เขียนโดยเฟบจากบันทึกการทดลองจริงทั้งหมด แล้วผู้เขียนมนุษย์ตรวจแก้ — ซึ่งถ้าคุณอ่านหมวดความจำข้างบนแล้ว จะรู้ว่าทำไมขั้นตอน "มนุษย์ตรวจแก้" ถึงไม่ใช่พิธีกรรม: ระบบที่ย่อความเก่งที่สุด ก็คือระบบที่เพี้ยนแบบแนบเนียนที่สุด*
